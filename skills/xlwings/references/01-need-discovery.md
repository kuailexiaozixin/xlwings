# 需求引导（xlwings customaddin 版）
这个文档专门面向零基础用户的需求澄清。后续 AI 在正式编码前，优先先做这一轮。
## 核心目标
不是让用户讲技术方案，而是帮助用户讲清楚：

- 现在怎么手工做
- 最痛的是哪一步
- 最终想看到什么结果
- 给谁用
- 用几次
- 在什么文件里用
- 处理后的结果是否需要随着原始数据的变化而自动更新（如果是，优先引导使用 UDF 自定义函数）
- 更适合哪种 xlwings 交付形态

## 首轮建议话术

> 你先别急着说技术名词，直接按你现在的真实操作流程描述就行。你希望用 Python 来处理 Excel 数据，还是希望在 Excel 公式里用 Python 函数？
> 另外，你希望这个结果是"点一下按钮跑一次"（RunPython 宏），还是"像公式一样，改了前面的数，后面自动就变了"（UDF 自定义函数）？
> 你把"从开始到结束"说一遍，我来帮你判断更适合做成什么工具。

## 场景判断

本文档只负责"问什么"：按必问问题清单（12 条）把需求问清楚、信息采集完整（含必要截图要求），把答案原样交给形态判定（三维判定模型），不在此预判形态。

## 需求复述后才能开工

推荐格式：

> 我先确认一下我的理解，你看对不对：
> 1. 你现在是在处理一个……表格
> 2. 你希望通过……方式触发（按钮 / 公式 / 自动）
> 3. 处理范围是……
> 4. 最终结果要变成……
> 5. 这个工具会给……使用
> 6. 所以我建议做成 xlwings 的……（xlam 带 Ribbon / xlam 纯 UDF / xlsm）
>
> 如果这些都对，我再开始写脚本和产物。

## 不要急着开工的情况

- 用户还说不清触发方式（按钮 vs 公式）
- 用户没有给样例文件或截图
- 用户只说"帮我自动化一下"，但没有说清输入和输出
- 用户给了现有文件，但还没讲清楚哪些旧功能和数据必须保留
- 用户想用 Python 但还不确定需要哪些第三方库

## 零基础用户沟通规范

如果用户说"我不懂编程"、"你帮我弄"：

1. **不要解释技术细节**。不要提装饰器、RunPython、配置表、pywebview
2. **用比喻说明**："我会给你做一个 Excel 里的按钮，点一下就能跑"
3. **只问业务问题**："处理什么文件？输入是什么？结果长什么样？"
4. **用户的角色是提需求，AI 负责全部技术实现**

### 沟通示例

> 用户：帮我做个工具，把一堆 Excel 文件合并成一个。
>
> AI（正确）：明白了。这些 Excel 文件格式一样吗？合并后需要保留哪些列？这个工具是您自己用还是给别人用？
>
> AI（错误）：好的，我会用 pandas 读取 Excel，然后用 xlwings 的 UDF 加 RunPython……（无用技术解释）
